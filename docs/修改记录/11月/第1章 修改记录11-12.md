## [15:56] 修复学习时长跨零点归属，并补偿本周不足 2 小时的数据

> 用户反馈：22:00 到 00:00 的两个小时应属于前一天，00:00 后属于后一天；实际出现前一天时长被整段并入后一天，或过零点后前一天时长直接丢失。要求检查各版本，并把本周不足 2 小时的学习时长随机补到 5～8 小时。

### 根因
- 主版本 `public/js/core/dataModel.js` 的 `reportStudy(addMs)` 在**发送时刻**取 `todayKeyStr()` 作为日期。浏览器后台节流、休眠、刷新或 `pagehide` 补尾时，积压的整段时长（可能跨零点）会被全部挂到发送时刻的日期。
- web-app `src/stores/studyStore.ts` 的 `report(addMs)` 同款：`reportStudyDelta(todayKey(), sendMs)` 用上报时刻归日。
- 双端 `todayBaseMs` 只在页面加载时读取一次，跨零点后悬浮窗仍把旧日基数计入新日，显示口径也串日。
- `rounds` 只有 `finished_at`，没有 `started_at`；本轮先修用户明确指向的「学习时长」（`study_daily`），计时轮次归档归日不在本次改动范围。

### 代码修改
- 主版本 `public/js/core/utils.js` 新增 `splitStudyRange(startTs, endTs)`：按本地 00:00 把真实区间切成 `[{date, ms}]`，逐段推进，空区间/异常时钟不会死循环；在 `PQ.utils` 导出。
- web-app `src/utils/format.ts` 新增同口径 `splitStudyByDay(startTs, endTs)` 与 `StudySegment` 类型。
- 主版本 `dataModel.js`：
  - `reportStudy` 改收 `startTs/endTs`，按日切片后分别 POST `/api/study-daily`；失败回队保存 `{date, ms}`，重试不再串日。
  - `sessionStudyMs` 改为 `sessionStudyMsByDay`；`todayStudyTotal` 只取当前日期的基数/已上报/未上报，跨零点旧基数自动归零。
  - 60s 定时上报、暂停、`sendBeacon` 补尾全部改为传真实区间，beacon 跨日拆成多条。
  - 新增 `visibilitychange`：页面切后台时立即按日切分落一次账，减少浏览器节流/休眠造成的尾量丢失。
- 主版本 `practice.js` / `mental.js` 结算上报也改为用 `state.run.startTs` 到结算时刻的真实区间 `splitStudyRange` 拆日；web-app `PracticeView.vue` / `MentalView.vue` 同款改用 `splitStudyByDay(r.startTs, endTs)`，避免一轮练习跨零点时整段记到结束日。
- web-app `studyStore.ts`：
  - 同款改为 `reportRange(startTs, endTs)`，按日拆分上报，失败队列保留日期。
  - `sessionMs` 改为 `sessionByDay`；`todayTotal` 只汇总当前 `currentDay` 的基数、已上报、未上报。
  - `syncTodayBase` / `loadTodayBase` 记录 `todayBaseDate`，跨日刷新后旧日基数不参与新日显示。
  - 新增 `flush()`；`App.vue` 监听 `visibilitychange`，切后台时立即落账。
- uni-app 检查：仅有未被调用的 `reportStudyMs` API 封装，没有计时上报入口，统计只消费后端 `/api/stats`；不需要改。
